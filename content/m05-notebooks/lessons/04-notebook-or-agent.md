### Two tools for the same job

Both can give grounded answers over a project's sources. They differ in **who
uses them and how**:

| | Notebook | Agent (Module 6) |
|---|---|---|
| **Feels like** | A shared project workspace | A specialist assistant you talk to |
| **Instructions** | Your standing brief at the start of a chat, or on a page | Built in; the same behaviour for every user |
| **Sources** | Curated, easy to add to day by day | A knowledge set chosen by the owner |
| **Notes and pages** | Built in | Not available |
| **Reuse across projects** | One notebook per project | One agent can cover a portfolio or a process |
| **Sharing cost** | Included with Chat and Premium | Users without Premium may create consumption costs. Check your tenant's setup |
| **Best for** | A lead's own project memory | A repeatable team process: handovers, "ask the project" |

### A simple rule

> **Start with a notebook. Build an agent when several people need the same
> instructions, repeatedly.**

For most Third Brains the answer is **both**: a notebook per project (curated
evidence and verified pages), and an agent that knows how your team asks
questions and writes handovers.

### Where a notebook falls short

A notebook depends on whoever curates it. If the standing brief is not pasted
each time, answers drift. If the team never adopts it, it becomes one more
folder that nobody trusts. An agent removes the repeated pasting, but it adds a
build, test and ownership job. Do not build one until the repeated need is clear.
